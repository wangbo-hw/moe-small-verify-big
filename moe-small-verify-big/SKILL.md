# MoE 以小验大

把可运行的大模型变成成本更低、保留目标计算路径的调试模型。先确认环境和裁剪语义，再采集、裁剪、验证。小模型通过只能证明已覆盖的路径，不能替代大模型规模、通信和内存验证。

## 操作命令手册

实际执行时读取 [references/commands.md](references/commands.md)。其中保留原经验的环境配置、权重转换、AIS-Bench 安装、原模型启动、路由采集、专家统计、裁剪和裁剪后评测命令，并将个人安装路径替换为本轮变量。根据已核实的脚本参数和硬件配置生成执行命令，不只输出原则性说明，也不将整份手册不加选择地执行。

优先从当前对话、项目文档和只读检查获取以下信息；仅询问仍然缺失、会影响执行的信息：

- 目标：纯推理、SFT/RL 调试，还是复现某个算子或通信问题；本轮需要准备方案还是实际执行。
- 原始权重、目标模型架构、可用镜像/容器、Python 环境、源代码和资源使用期限。
- 校准数据、独立验收数据，以及保留专家数、质量损失和资源预算的要求。
- 是否已有可运行的原模型基线、采集补丁、统计脚本和裁剪脚本。

已有脚本应先检查源码和 `--help`；缺失时优先从上述入口取得实现，不凭历史文件名构造命令。

## 环境与路径适配

先读 [references/environment.md](references/environment.md)。所有路径都在实际执行环境中解析；主机路径、容器路径和本地编排路径分别记录。旧材料中的用户名、版本、设备编号和目录只是案例。

建立本轮 `runtime-map.json`，记录已确认的解释器、源码真实导入位置、权重、脚本、CANN/自定义算子、数据与输出目录。只有映射已核实的命令才能执行。安装或升级依赖、转换权重、修改配置都应有明确理由，不作为例行前置操作。

## 采集与裁剪

执行前读 [references/routing-and-pruning.md](references/routing-and-pruning.md)。按以下依赖推进：

1. 读取配置及权重布局，画出逐层 routed/shared/hash/MTP 结构，区分保留专家数和每 token 激活专家数。
2. 验证原模型服务和基线，再在实际路由路径安装观测，记录逻辑专家 ID、层、请求、阶段和必要的 rank 信息。
3. 用固定校准样本采集有效 token 路由，排除 dummy/warmup/padding 和重复 rank 记录，汇总逐层频次与保留覆盖率。
4. 先验证裁剪计划，再写入全新输出目录；同步切片专家权重、router 和相关状态，保存 old→new ID 映射。
5. 校验输出配置、张量、索引和保留模块，关闭路由采集后启动裁剪模型。

默认只裁剪学习式路由的 routed experts。保留 shared experts、已确认的 hash 层及非目标结构；额外结构变化必须属于用户请求且单独验证。不能把 DeepSeek-V4 的层号、专家数或模型实现直接套给 HY4。

需要移植已有 vLLM/vLLM-Ascend 补丁时，可结合环境中已有的 `small-verify-big-patch`；本技能的环境探测和裁剪校验仍必须完成，不继承案例中的固定 TP、量化方式或源码路径。

## 验收与大模型回归

读 [references/validation.md](references/validation.md)，按任务选择推理质量、训练更新或训推一致性验收。

- 固定数据 ID、tokenizer/chat template、生成参数和评测器，比较原模型与裁剪模型的质量和资源消耗。
- 训练任务继续验证真实反向、梯度和参数更新；前向通过不代表反向正确。
- 训推一致性比较同一 checkpoint、同一 response token、更新前 actor 重算与 rollout；明确概率 Pearson 与 logprob Pearson 的区别。
- 将修复带回大模型时，单独验证实际通信拓扑、权重同步、长序列和内存峰值。

遇到结构不支持、映射不完整、权重校验失败或资源被他人占用时，停止依赖该条件的操作，继续可独立完成的 CPU 检查。不要通过覆盖原权重、删容器或终止他人任务来绕过问题。
