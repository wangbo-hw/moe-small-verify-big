# 专家采集与结构裁剪

原模型启动、采集、`stat_moe.py` 和 `expert_pruned.py` 的参数化命令见 [commands.md](commands.md)，执行前用本页核对结构与映射。

## 确认逐层结构

结合模型配置、真实实现及权重 header/索引建立逐层表：层号、路由类型、routed 数量、shared 数量/宽度、每 token 激活数、router/校正 bias、hash 表、MTP 和量化布局。字段可能位于嵌套 text config，不能只检查配置顶层。

`KEEP_EXPERTS=64` 表示每个目标层保留 64 个 routed experts；`experts_per_token=6/8` 表示每个 token 的激活数，两者不是同一个 top-k。仅缩减专家池时保留原激活数和路由算法，并检查 `KEEP_EXPERTS >= experts_per_token`。分组路由还需检查组数、每组候选数和分组 top-k 的约束；不满足时重新制定裁剪方案，不能悄悄改算法凑形状。

hash 路由层默认保留全部原专家及原 hash 映射。若某些层保留原数量、其他层裁剪，loader 必须支持逐层不同专家数；仅修改全局 `n_routed_experts` 可能造成保留层也被错误实例化。未支持这种结构时，先适配并验证 loader，或明确报告该方案当前无法运行。

shared expert 默认原样保留。注意 shared 与 routed 可能复用 MLP 构造代码但 clamp/激活配置不同；禁止因为共用代码而把 routed 配置强加到 shared。MTP、embedding、attention、norm、LM head 的处理逐项记录，不按名称相似推定能删除。

## 在真实路由路径观测

确认当前版本真正执行的 router/fused MoE 实现。补丁适配先读目标实现与 diff，保存原文件、提交、哈希和变更记录；不能直接用另一版本的完整文件覆盖。导入、形状检查通过后才进行小请求验证。

采集实际用于 dispatch 的选中专家，保留原路由与计算行为：

- 保存逻辑专家 ID，位于 EP 分发、local ID 转换、`log2phy`/负载均衡重映射之前；若只能拿到物理 ID，必须有同次运行的反向映射。
- 记录全局层号、prefill/decode、请求/序列、有效 token、rank/副本来源，以及采集补丁版本；字段按实现能力选取，但需足以过滤和去重。
- TP rank 若复制了相同逻辑路由，只选一份或验证后去重；DP 副本上的不同请求应合并。不能把 EP rank 的局部 ID 直接当作全局专家编号。
- 对统一目标请求比较采集开/关的输出，确认观测没有改变 top-k、权重或 dtype。异步写出需要确认成功与完整性。

若使用 `TOPK_SAVE_PATH`，先确认补丁真的读取该变量并产生本轮记录。采用独立目录、低并发与该版本支持的 eager 模式，避免在计算图采集中混入逐 token 文件 I/O。采集量较大时分片、聚合，记录丢弃/截断计数，不能把不完整 dump 当完整样本。

原模型不能在当前资源上启动时，先解决原模型采集的资源或后端支持，或选择另一个经用户认可的可运行校准模型并标注范围；不能把随机裁剪模型的频次宣称为原模型频次。

## 排除 dummy、warmup 与 padding

服务就绪不代表已有文件全是数据集记录。优先在 hook 中标记 phase/request，并在真正采样时开启采集。若 hook 支持运行时重置/切换目录，验证该机制后再使用；修改启动 shell 的环境变量不会改变已运行服务。

无动态开关时，选用可验证的请求边界或文件偏移隔离 warmup，并保存边界证据。无法可靠分离时，先修改采集方式再采集。不要照抄 `rm -rf topk_ids_by_layer/*`；并发写入时清空目录还会导致统计不完整。

## 汇总频次与生成映射

固定校准数据集、split、样本 ID、提示模板、生成参数和 seed。记录输入 token 与生成 token 的贡献。每层检查有效记录数量、专家 ID 范围、缺层、重复、padding、异常重复 ID，以及计数是否与有效 token×激活数一致。

在确认去重和过滤后按频次选取每层专家；相同频次采用固定的 ID 次序打破平局。报告保留选择次数占总选择次数的比例，必要时另报路由权重质量覆盖率；频率覆盖率不是准确率保证。

保存每层完整频次、选中旧 ID 和明确的 old→new 映射。顺序可以按频次或原 ID，但专家权重、router 和所有相关元数据必须使用同一顺序。

## 写出裁剪权重

先读取统计/裁剪脚本的源码和 `--help`，确认输入 JSON schema、输出位置、支持的 tensor 布局和默认 skip 层。旧脚本可能用 `--json-path`，另一个实现用 `--topk-json`；不能互换。只读计划应列出每项 tensor 的 copy/slice/rename/drop、源和目标 shape、切片轴及预计大小。

确认以下不变量后再写入新目录：

- 原模型只读，目标不与源相同或位于源目录内部；已有输出不覆盖。
- 每层选中的 ID 唯一且有效；router logits 行/列、校正 bias、专家 gate/up/down 权重等使用相同映射。
- packed expert 张量先确认布局，不能仅凭某维大小恰好等于专家数就切片；量化 scale/zero point/分组元数据随对应张量一起处理。
- shared/hash/非目标模块保持原值和结构；对未改变模块逐 tensor 验证，而不是比较可能重新分片后的文件哈希。
- 配置、逐层数量、state dict key、safetensors 索引、分片和 total_size 相互一致；tokenizer、必要自定义代码和模板保留。

完整权重较大时分片读取与写出，并预留源+目标+临时文件空间。使用未完成目录或完成标记区分部分输出；只有数据与索引校验通过后才能启动服务。保留映射和源文件校验信息，不能把“文件少了”当作裁剪正确的证据。
